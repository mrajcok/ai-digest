The Economics of Agent Optimization: From pilots to measurable returns

Microsoft introduces a framework for managing AI costs as production deployments scale, focusing on treating AI as a “managed investment system."

  • Microsoft Foundry is positioned as the core platform, enabling runtime request optimization via features like a Model Router that directs prompts to cost-optimized models (cost, quality, balanced modes), varied deployment options (Global, Data Zone, Regional), and caching mechanisms.
  • Agent optimization is addressed through automated testing of prompts, models, and tools using the Agent Optimizer, alongside tools like Toolboxes (sending only necessary tool definitions) and various memory types (procedural, user, session) to reduce repeated token usage.
  • Spend governance is enhanced via Azure API Management’s AI Gateway for implementing token rate limits and quotas, and future integration of native budget enforcement within Foundry and tenant-wide controls through Agent 365.
  • Cost visibility and reporting are available at model- and deployment-level within Foundry, with plans to expand attribution down to individual agents and sessions, integrating with Azure Cost Management for overall budget and billing management.

How to build an AI agent: A simple guide for anyone

Microsoft details how to build AI agents using Microsoft 365 Copilot.

  • Users can build agents without code, starting by defining the problem the agent will solve, rather than focusing on the technology itself.
  • Microsoft 365 Copilot allows users to create a new agent via the "Agents" section, where the Copilot will generate a draft based on plain language descriptions.
  • Agents can be refined through instructions defining behavior, tone, and tasks, and can be connected to data sources like emails, documents, and SharePoint sites.
  • The article provides examples of agents automating tasks like status report creation, email triage, and weekly report generation, and emphasizes iterative testing and refinement.

Teaching AI to speak the language of pathology

Microsoft Research and Paige (now Tempus) announced PRISM2, a pathology foundation model designed to connect visual patterns in tissue with diagnostic language.

  • PRISM2 was trained on both tissue images and language from pathology reports, creating millions of question-and-answer examples.
  • The model reportedly matched or exceeded the performance of specialized cancer-detection systems on prostate cancer, breast cancer, and breast lymph node metastasis detection—without requiring separate models for each task.
  • PRISM2 can operate using images only or images and text, allowing for prompt-based interaction.
  • Full model weights are publicly available for research use on Hugging Face.

Fantasy Premier League Companion gives managers a new tool for success

Fantasy Premier League Companion, powered by Copilot, offers AI-driven advice for the official Premier League fantasy football game.

  • The Companion utilizes Microsoft Foundry, Azure OpenAI, and GPT 5.4, alongside official Premier League data.
  • Users can ask both basic and specific questions about their FPL teams, such as player suggestions or analysis based on specific metrics (e.g., shots in the box).
  • The tool is designed to assist managers in making informed decisions, not to automatically run their teams or predict FPL points.
  • It aims to lower the barrier to entry for new players by providing conversational access to game data and explanations of core concepts, while also offering advanced data insights for experienced players.

AT&T and Microsoft scale trillion-token workloads with Microsoft Foundry and AMD

AT&T scaled AI development of its Open Telco (OTel) 2.0 models using Microsoft Foundry and AMD GPUs.

  • AT&T leveraged Microsoft Foundry Managed Compute to deploy and optimize workloads across multiple open models, including Phi-4, OSS-120B, and Gemma-4.
  • Phi-4 processed over 700 billion tokens monthly for data preparation and synthetic data generation within the OTel2.0 workflow.
  • The deployment utilized approximately 530 GPUs, including 430 AMD Instinct™ MI300X GPUs, offering infrastructure flexibility.
  • AT&T processed approximately 1 trillion tokens and saved tens of millions of dollars by using open models with Foundry Managed Compute, compared to using frontier models.
