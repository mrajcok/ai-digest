Coding sessions are longer and use more context. Claude Opus 5.5 is built with that in mind. | Claude by Anthropic

Anthropic has released Claude Opus 5.5, optimized for the evolving patterns of developer coding sessions. Analysis of Claude Code usage from March to September 2026 shows sessions are becoming longer and more context-heavy – 2.6x more context per request, with a token ratio of 324:1 (input to output). Despite more model calls per prompt (40% increase) and longer session durations (3.3x), interruptions are down 68%.

Opus 5.5 addresses these trends with three key improvements. First, input and output token costs are reduced by 20%, and cached token costs by 60%. Second, improvements to the Claude Code harness boost cache hit rates, decreasing cache misses by over 50% and allowing longer cache lifetimes (now available to API key and cloud provider users). Finally, Opus 5.5 demonstrates a reduction in the number of turns needed to complete tasks – Zeta Labs saw nearly half the cost and twice the completion rate on harder tasks compared to Opus 5 – with a 30% increased output speed.

Users are advised to monitor cached read usage within Claude Code and adopt practices like choosing a model at the start of a session and compacting context to maximize cost efficiency. Detailed cost comparisons for specific tasks can be found in the related post, "What a task costs on Opus 5.5."

Claude Tag now supports personal connectors in channels | Claude by Anthropic

Anthropic has added support for “personal connectors” to Claude Tag, currently in beta. This allows Claude, when accessed within a Slack channel, to utilize connectors linked to an individual user’s account – such as their calendar, Google Drive, or CRM – in addition to the channel’s pre-approved, admin-managed connectors. The user controls how information from these personal connectors is surfaced, choosing between automatic posting (with sensitive content review) or manual review before publication to the channel.

This feature expands Claude’s access to information typically behind individual logins. For example, a user can ask Claude to compare a personal Google Doc to recent GitHub commits, with Claude accessing the document via the user’s drive connection and the commits via the channel’s GitHub connection. Importantly, all activity through a personal connector is logged under the user’s account, while channel activity remains under the channel’s service account.

The rollout begins now for Team plan users, with Enterprise access to follow. Administrators on Enterprise plans will be able to require review of all responses utilizing personal connectors. Connectors used for unattended actions, or those requiring cross-channel access, should still be managed at the channel level by administrators.

Anthropic research · 2026-09-24

Project Swap: What happens when agents trade for us?

Anthropic’s Project Swap investigated how well AI agents – specifically those powered by Claude – can trade on behalf of people. The experiment involved 201 Anthropic employees trading books, with each employee first chatting with Claude to determine their reading preferences. Agents then negotiated with each other on a digital trading floor. The study found that agents were surprisingly good at representing their participants’ preferences based on a short (averaging 216 words) conversation, matching their rankings 61% of the time. However, the market’s efficiency was limited more by the agents’ imperfect understanding of participant preferences than by the negotiation process itself.

Further analysis revealed that the model powering the agent (Haiku, Sonnet, Opus, or Fable) had a greater impact on negotiating outcomes than the specific instructions given to the agent ("ruthless" vs. "prosocial"). Stronger models led to more efficient markets. Participants indicated they would trust such an agent with roughly 30% of their yearly book budget, about 75% of what they’d trust a human friend with. The researchers highlight the importance of verifying agent understanding of user preferences – proposing a "test" where agents demonstrate their understanding before acting on behalf of a user – and establishing clear rules for agent marketplaces to ensure positive outcomes for all involved.

Advancing Private AI Compute with secure, server-side memory

Google announced an update to its Private AI Compute platform adding private, server-side memory to enable persistent, cross-device AI assistance while maintaining on-device privacy standards.

  • The new architecture uses a persistent memory layer functioning as an encrypted "digital vault" in the cloud, accessible only with cryptographic keys held on the user’s devices.
  • AI models access data through authenticated, end-to-end encrypted channels to a “secure enclave” that temporarily decrypts data in isolated memory, processes the request, and immediately re-encrypts it.
  • The system leverages hardware-enforced secure enclaves, encrypted channels, and per-user databases shielded by device-derived encryption keys to ensure data privacy and user control.
  • Google is publishing a tamper-proof public record of their server software to allow verification of authenticity and unaltered status prior to data transmission, alongside an updated Private AI Compute Technical Brief detailing system architecture and security proofs; an independent audit by a cybersecurity firm was also conducted.

Mistral AI blog · 2026-09-09

Modernizing complex legacy code with AI agents.

Mistral AI successfully migrated 40,000 lines of Fortran 77 code for a European energy operator to C++, addressing the challenge of maintaining and extending aging scientific codebases. A key aspect of their approach was establishing a “parity harness” – a system to verify numerical equivalence between the original Fortran and the translated C++ code, using exported state snapshots and a test framework. This ensured accuracy before extensive agent-driven translation began.

Initial attempts at fully autonomous translation produced syntactically correct but structurally poor code, essentially “Fortran retyped in C++.” Subsequent iterations employed structured agent workflows, combining AI “agents” with human oversight – a “planner,” “coder,” “tester,” and reviewer – focusing on manageable code modules (~10,000 lines). They also leveraged agents to document the legacy codebase by analyzing its call graph and incorporating information from existing PDFs using Mistral's OCR technology.

The project highlights three key principles for successful legacy code modernization: prioritize building a validation harness before coding, ensure comprehensive documentation, and implement structured workflows combining AI autonomy with human review gates. Approximately 40,000 lines were converted in the first sprint of a 300,000-line codebase.
