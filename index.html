Anthropic blog · 2026-08-14

Maximizing the value of your Claude Code sessions | Claude by Anthropic

Anthropic’s blog post details techniques for cost-efficient sessions with Claude Code. The core claim is that managing token usage – both input and output – directly impacts the cost of each task. Input tokens are cheaper, while output tokens are roughly 5x more expensive, and caching significantly reduces the cost of re-used tokens (to 0.1x the input price).

Key recommendations include using /clear between tasks to prevent irrelevant context from increasing token usage, setting the model and effort level at the start of a session to avoid prompt cache invalidation, and utilizing @-mentions for files instead of paths to skip read calls. Users can further optimize by running /context to review loaded content, /compact to summarize conversations while the cache is valid, and leveraging subagents for tasks generating substantial output. Commands executed during a session also contribute to the context, so employing quiet flags or running them in subagents is advised.

Anthropic news · 2026-08-14

How Claude's text watermarking works

Anthropic will implement a text watermarking system in future versions of Claude to comply with the August 2, 2026 EU AI Act, which requires marking AI-generated content. This system, based on Google DeepMind’s SynthID-Text method published in a 2024 Nature paper, works by subtly influencing word choices during text generation – selecting from equally valid options based on a cryptographic key rather than pure randomness.

The watermarking is designed to be undetectable to readers and has shown no impact on text quality, creativity, or readability in internal and Google DeepMind testing. It doesn’t add visible characters or increase costs. The watermark indicates the likelihood that Claude contributed to a text, but cannot identify users or definitively prove AI authorship, especially in heavily edited or short samples, or for exact outputs like code.

Anthropic will also attach cryptographically signed metadata to files created or processed by Claude, using the C2PA standard, and plans to offer a watermark detection API. The change will be applied globally, though regional scoping is being evaluated.

AWS blog · 2026-08-14

Custom reward functions for multi-turn reinforcement learning with Amazon Nova Forge

Custom reward functions are critical for effective multi-turn reinforcement learning with Amazon Nova Forge, particularly when using reinforcement fine-tuning (RFT) and Group Relative Policy Optimization (GRPO).

  • Amazon Nova Forge allows you to bring your own orchestration (BYOO) to run reward logic in your environment for multi-turn RL, handling rollouts, message passing, and state across turns.
  • RFT uses a reward function—code you write—to score model outputs and adjust weights to maximize cumulative reward across a sequence of interactions, unlike supervised fine-tuning which relies on annotated examples.
  • Effective reward design combines outcome rewards (goal completion), behavioral rewards (desired intermediate steps), and penalties to discourage failures—ensuring a balanced learning signal and preventing gaming of individual components.
  • When executing model-generated code within the reward function, security measures like isolated environments, resource limits, and input/output validation are essential to prevent exploitation and maintain system integrity.

Mistral AI blog · 2026-08-04

Introducing Shieldstral.

Mistral AI has released Shieldstral, a 3 billion parameter open-weights model designed for multimodal safety classification. The core innovation is framing content moderation as a question-answering task, allowing users to define safety policies in plain language at inference time without requiring model retraining. Shieldstral accepts a structured input consisting of an instruction, a yes/no query representing the safety policy, and the content to be evaluated (text, image, or both), then outputs a calibrated safety score.

The model is designed to rival the performance of models up to seven times its size on text safety and achieves state-of-the-art results on multimodal moderation tasks. It was trained on a combination of real and synthetically generated data and requires only a single 16GB NVIDIA GPU for operation. Shieldstral is available under the Apache 2.0 license and was created utilizing Mistral’s Forge platform.

Key to Shieldstral's performance is its approach to data handling: unifying diverse datasets, teaching the model to discriminate between similar policies rather than memorizing labels, incorporating image data, and combining multiple fine-tuned checkpoints.

Mistral AI blog · 2026-07-09

Your Prompts and Skills need a system of record.

Mistral AI’s Studio now offers a system of record for managing AI prompts and skills, addressing the common enterprise problem of scattered and unmanaged instructions. This feature treats prompts as production assets, providing version control, ownership, and audit logs to ensure AI behavior is governed and traceable. Every prompt or skill receives an immutable version, a designated owner, and can be labeled for classification (e.g., “Production” vs. “Staging”).

The system aims to accelerate iteration by allowing quick testing of changes without requiring full CI/CD pipelines, while still maintaining enterprise-level controls for deployment. Domain experts can directly improve production instructions, triggering existing CI/CD processes via the Mistral SDK. Importantly, Studio connects these governed assets to runtime behavior through observability, lineage, and telemetry, tracing outputs back to specific versions and usage data.

This differs from standalone prompt catalogs by providing a closed-loop system where behavior is defined, monitored, and improved against a single source of truth, helping organizations maintain compliance and reduce risk related to ungoverned AI instructions. The feature is currently available to Mistral Studio customers.
