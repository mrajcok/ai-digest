The AI-Native SDLC playbook | Claude by Anthropic

Anthropic’s blog post details how to transform the Software Development Lifecycle (SDLC) to fully leverage AI, specifically their Claude Code model. The core claim is that, with AI handling code generation, the bottleneck in development has shifted away from writing code itself and toward planning, review, testing, and deployment. To address this, they propose an “AI-native SDLC” – a looped process embedding AI at each stage – replacing the traditional linear flow.

This involves creating committed artifacts at each stage (like intent.md for initial ideas, spec.md for design, and plan.md for implementation plans) stored in version control, which then trigger the next phase. They introduce "plays" – modular steps for integrating Claude into each SDLC stage – focusing on automated handoffs and continuous evaluation. Key to this is using Claude to synthesize requirements from stakeholders into machine-readable formats, automating design tasks, generating code with integrated tests, and using AI-driven review layers alongside human oversight, particularly for critical or regulated code.

The post emphasizes institutional knowledge as code, through CLAUDE.md files that maintain project-specific context, and "skills" – reusable, versioned instructions applied by Claude to enforce standards and policies. They also discuss leveraging hooks for deterministic guardrails and the use of parallel sessions and sub-agents to increase engineer throughput.

AWS blog · 2026-08-21

Reduce RAG costs on Amazon Bedrock with query-aware compression

Reduce RAG costs by filtering retrieved chunks with a smaller model before sending context to the primary model.

  • Amazon Bedrock enables a “query-aware compression” pattern where a smaller, lower-cost model (e.g., Anthropic Claude Haiku) filters retrieved chunks based on the user query.
  • This reduces the number of input tokens sent to the primary model (e.g., Anthropic Claude Sonnet), lowering costs, and potentially reducing hallucination by removing irrelevant context.
  • The implementation uses an AWS Lambda function with the Amazon Bedrock Converse API, adding a compression step before the final answer generation. The pattern achieved 33% cost savings in testing.
  • Key considerations include the price ratio between the models, inference speed, and maintaining answer quality – with tests showing minimal impact on correctness and a reduction in hallucination rate.

Mistral AI blog · 2026-08-20

Agentic Search. More accurate and efficient results from your AI systems.

Mistral AI has introduced Agentic Search, a new retrieval method designed to improve the accuracy and efficiency of AI systems when navigating complex data. Unlike traditional Retrieval-Augmented Generation (RAG) which relies on a single search pass, Agentic Search employs a multi-step loop of finding, inspecting, and verifying information using five tools: search, open, navigate, read, and grep. These tools function similarly to file system operations, allowing the model to refine searches and inspect source material directly, rather than being limited to pre-retrieved chunks.

Testing on FinanceBench (SEC filings) and OfficeQA Pro (Treasury Bulletins) demonstrates significant gains. With the Mistral Medium 3.5 model, adding the agentic loop improved accuracy on FinanceBench by +47.3 percentage points, and navigation tools added another +8.7pp. On OfficeQA Pro, accuracy increased by +27.1pp for MM 3.5 and a substantial +45.6pp for the larger GLM-5.2 model, to 51.9%. The iterative approach also reduced token usage by up to one-third and lowered p90 latency by up to 39.6% compared to one-shot RAG.

Agentic Search is available through the Mistral Search Toolkit, within Mistral’s Libraries in Studio and Vibe, and is designed to work with both cloud and on-premises deployments. The framework is model-agnostic and doesn't require fine-tuning, with performance expected to scale with future model improvements.

Mistral AI blog · 2026-08-04

Introducing Shieldstral.

Mistral AI has released Shieldstral, a 3 billion parameter open-weights model designed for multimodal safety classification. The core innovation is framing content moderation as a question-answering task, allowing users to define safety policies in plain language at inference time without requiring model retraining. Shieldstral accepts a structured input consisting of an instruction, a yes/no query representing the safety policy, and the content to be evaluated (text, image, or both), then outputs a calibrated safety score.

The model is designed to rival the performance of models up to seven times its size on text safety and achieves state-of-the-art results on multimodal moderation tasks. It was trained on a combination of real and synthetically generated data and requires only a single 16GB NVIDIA GPU for operation. Shieldstral is available under the Apache 2.0 license and was created utilizing Mistral’s Forge platform.

Key to Shieldstral's performance is its approach to data handling: unifying diverse datasets, teaching the model to discriminate between similar policies rather than memorizing labels, incorporating image data, and combining multiple fine-tuned checkpoints.
