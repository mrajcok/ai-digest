Anthropic research · 2026-11-13

Building strong safety evaluations

Anthropic outlines recommendations for building robust AI safety evaluations, emphasizing that a safety claim is only as strong as the evaluation supporting it. They advocate for assembling diverse teams – including both domain and methods experts – to design evaluations that measure harm propensity rather than just model capabilities. Crucially, evaluations should be run in isolated, monitored environments to prevent unintended actions.

The core of their approach focuses on designing evaluations to answer specific questions (observational vs. causal), accurately measuring the intended construct (like appropriate response rate in sensitive topics instead of simple refusal), and ensuring results generalize to real-world scenarios through multi-turn simulations that capture nuanced interactions. They stress the importance of rigorous grader validation against human labels, preregistering evaluation plans, and fully reporting statistical uncertainty.

Anthropic shares examples from their system cards and tools like Petri, highlighting a recent case where a system prompt update improved responses related to suicide and self-harm from 60% to 94% on claude.ai. Following these recommendations—measuring the right thing, validating graders, and reporting uncertainty—is key to trustworthy AI safety assessments.

Google research · 2026-11-11

AlphaGenome 2: Deciphering how cells read DNA to better understand disease

AlphaGenome 2 predicts how DNA sequences and variations impact specific human cell types, offering a significant improvement in variant predictive performance over prior work.

  • AlphaGenome 2 is a conditional model that predicts DNA effects for a single biological condition (tissue, cell type, or state) at a time, improving accuracy compared to the parallel approach of AlphaGenome 1.
  • Trained on over 107 million individual cell profiles across 68 tissues, the model identifies nearly twice as many variants that change gene expression in cells compared to the original AlphaGenome.
  • AlphaGenome 2 can generalize to new single-cell experiments without retraining, predicting effects in unseen cell states using only a small sample of cells.
  • The model predicts core DNA function readouts (gene expression, histone modifications, chromatin accessibility) and newly includes DNA methylation, with precomputed predictions available for trait-associated variants across hundreds of cell/tissue conditions.

AWS blog · 2026-11-13

Build a model improvement flywheel with Amazon SageMaker HyperPod Data Capture

Amazon SageMaker HyperPod now offers Data Capture, a built-in capability for recording live inference data to Amazon S3.

  • Data Capture operates at three tiers – endpoint, load balancer, and model pod – allowing flexible configuration for compliance, monitoring, or training data collection.
  • It captures full request/response payloads, ALB access logs, and event metadata with minimal latency impact and no downtime.
  • Tier 3 allows capturing full payloads, which requires using sampling, AWS KMS encryption, S3 lifecycle rules, and PII redaction to protect sensitive data.
  • A complete example demonstrates capturing data, analyzing it with Athena, labeling it with SQL, fine-tuning a Qwen2.5-3B-Instruct model using the captured data, and redeploying—all within a single HyperPod cluster.
AWS blog · 2026-11-13

Cost attribution and controls for AI developer and productivity tools on Amazon Bedrock

Amazon Bedrock now offers zero-instrumentation cost attribution, tracing inference calls to the IAM principal making them, with data flowing into AWS Cost and Usage Reports (CUR 2.0) and Cost Explorer.

  • Attribution works for all tools invoking Bedrock via the bedrock-runtime or bedrock-mantle endpoints, including Claude Code, Claude Desktop, OpenAI Codex, ChatGPT Work, and OpenCode.
  • Configuration involves setting up IAM Identity Center with an external identity provider for per-user attribution, enabling session tags, and configuring Athena queries for cost visibility.
  • Multiple attribution mechanisms are available: IAM principal tracking, Application Inference Profiles, Projects/Workspaces, and per-request metadata tagging, which can be combined for different levels of granularity.
  • Prerequisites include an AWS account, IAM Identity Center setup, an external IdP with SCIM provisioning, AWS CLI v2, CUR 2.0 with IAM principal data enabled, cost allocation tags activated, and an Athena table configured for querying CUR 2.0 data.
AWS blog · 2026-11-13

Cost-optimizing AssemblyAI speech-to-text inference on AWS with Amazon EC2 Spot

  • AssemblyAI optimized speech-to-text inference costs by 70% using a combination of Amazon ECS, EC2 Spot Instances, and Amazon SQS.
  • The architecture leverages ECS capacity providers with a mix of On-Demand and Spot Instances, diversifying across NVIDIA GPU instance families (g4dn, g5, g6 – T4, A10G, and L4 GPUs respectively).
  • Amazon SQS is used as a queue-based retry mechanism to recover from Spot Instance interruptions; incomplete jobs are returned to the queue for processing by healthy instances.
  • Regional deployment in AWS Regions like US West (Oregon) and Europe (London) supports data residency requirements, running independent copies of the inference architecture in each region.
