The Claude Science product guide | Claude by Anthropic

Anthropic has released Claude Science (currently in beta), an AI workbench specifically designed for life sciences research. It’s positioned within the broader Claude family—including Chat, Cowork, Code, and Managed Agents—and aims to address the gap between high interest (91% of scientists want more AI) and low implementation (14% fully implemented) due to concerns about trust and reliability.

Anthropic provides a three-phase adoption roadmap (Foundation, Pilot, Scale) with associated metrics for measuring success. Use cases include single-cell RNA-seq clustering and drafting scientific methods sections. The software's focus is on scientific validity, supported by five key design choices highlighted in the guide.

Anthropic blog · 2026-08-18

How Claude Tag serves as Anthropic’s first responder for CI/CD failures | Claude by Anthropic

Anthropic has implemented “Claude Tag,” an agent powered by Claude 3, to serve as the first responder for CI/CD failures. This agent operates within their on-call Slack channel, providing initial incident reports within 15 minutes and often identifying the root cause within 4 minutes. Claude Tag maintains memory of the channel’s history and integrates with tools like Datadog, Grafana, GitHub, and Kubernetes via MCP Connectors.

The system utilizes markdown files, committed to a GitHub repository, to store instructions, policies, and a “lessons learned” log for continuous improvement. Claude Tag not only detects incidents—including by analyzing data and reducing alert fatigue—but also triages them, investigating dependencies and synthesizing findings into reports. It can even handle automated fixes, such as managing feature flags and suggesting PRs. A separate “ci-weather” agent compiles incident data for company-wide communication. The setup requires a Claude Team or Enterprise plan and can be streamlined using Anthropic’s provided on-call setup kit.

How Claude is accelerating protein design and analytical chemistry

Claude (Mythos Preview and Opus 4.8) successfully designed protein binders against 14 of 15 targets, achieving 22-35% success rates – exceeding typical protein design campaigns (10-15%). Some designs exhibited higher affinities than previously published results. In a separate test, Claude Opus 5 analyzed raw NMR and LC-MS data, matching a contract lab’s analysis of hydrogen counts (within 0.08 ¹H) and purity (96.4% versus 96.33%) in 23 and 19 minutes, respectively.

These experiments demonstrate Claude’s ability to accelerate both the design of new molecules and the analysis of existing ones. The protein design campaign utilized specialized protein design and folding models with up to 12,500 NVIDIA H100 hours of compute. The analytical chemistry task involved processing proprietary instrument files without vendor software.

These capabilities are currently limited in access due to dual-use concerns, but Anthropic plans access programs for scientists and continues to improve the models’ scientific judgment. Further technical details, prompts, and data are available in accompanying reports.

How Axonius built secure multi-tenant AI agents on Bedrock AgentCore

Axonius deployed secure, multi-tenant AI agents using AWS Bedrock AgentCore, maintaining a siloed architecture for tenant isolation.

Improve contract search accuracy with auto-generated filters in Amazon Bedrock

  • Amazon Bedrock now supports auto-generated filters for improved contract search accuracy using AI-Driven Annotation (AIDA) and a RAG architecture.
  • The solution utilizes implicit filtering, applying metadata-based conditions (like date ranges or parties) before semantic search to narrow the document pool.

AWS blog · 2026-08-18

How Jumio built a real-time feature store on AWS

  • Jumio built a real-time feature store on AWS to address data duplication, manual deployment, and latency challenges in fraud detection, achieving sub-100ms prediction latency.
  • The architecture utilizes Amazon Kinesis Data Streams for real-time ingestion, Apache Flink for processing and enrichment, and Amazon SageMaker Feature Store (with ElastiCache for Valkey providing an in-memory store) for low-latency feature serving.
  • A parallel batch processing path uses Amazon Data Firehose and Amazon EMR with Apache Iceberg tables for offline feature storage used in model training and analysis.
  • Performance metrics achieved a 95th-percentile read latency of 16.9ms and a 50th-percentile write latency of 18.6ms, with $120,000 in annual cost savings through storage optimization in Amazon SageMaker Feature Store.

Mistral AI blog · 2026-08-04

Introducing Shieldstral.

Mistral AI has released Shieldstral, a 3 billion parameter open-weights model designed for multimodal safety classification. The core innovation is framing content moderation as a question-answering task, allowing users to define safety policies in plain language at inference time without requiring model retraining. Shieldstral accepts a structured input consisting of an instruction, a yes/no query representing the safety policy, and the content to be evaluated (text, image, or both), then outputs a calibrated safety score.

The model is designed to rival the performance of models up to seven times its size on text safety and achieves state-of-the-art results on multimodal moderation tasks. It was trained on a combination of real and synthetically generated data and requires only a single 16GB NVIDIA GPU for operation. Shieldstral is available under the Apache 2.0 license and was created utilizing Mistral’s Forge platform.

Key to Shieldstral's performance is its approach to data handling: unifying diverse datasets, teaching the model to discriminate between similar policies rather than memorizing labels, incorporating image data, and combining multiple fine-tuned checkpoints.

Mistral AI blog · 2026-07-09

Your Prompts and Skills need a system of record.

Mistral AI’s Studio now offers a system of record for managing AI prompts and skills, addressing the common enterprise problem of scattered and unmanaged instructions. This feature treats prompts as production assets, providing version control, ownership, and audit logs to ensure AI behavior is governed and traceable. Every prompt or skill receives an immutable version, a designated owner, and can be labeled for classification (e.g., “Production” vs. “Staging”).

The system aims to accelerate iteration by allowing quick testing of changes without requiring full CI/CD pipelines, while still maintaining enterprise-level controls for deployment. Domain experts can directly improve production instructions, triggering existing CI/CD processes via the Mistral SDK. Importantly, Studio connects these governed assets to runtime behavior through observability, lineage, and telemetry, tracing outputs back to specific versions and usage data.

This differs from standalone prompt catalogs by providing a closed-loop system where behavior is defined, monitored, and improved against a single source of truth, helping organizations maintain compliance and reduce risk related to ungoverned AI instructions. The feature is currently available to Mistral Studio customers.

Ars Technica news · 2026-08-18

Microsoft Copilot reveals secret input that allowed it to be hacked

  • Microsoft 365 Copilot was found to be vulnerable to a URL-based attack allowing data exfiltration with a single click.
  • Researchers at Varonis discovered the vulnerability by querying Copilot about its own guardrails, which led Copilot to reveal the undocumented prompt parameter ?autorun=1.
  • Combining ?autorun=1 with the ?q= parameter allowed attackers to bypass user consent and automatically execute prompts, including those designed to steal data.
  • Microsoft mitigated the vulnerability in February and implemented further fixes in August by preventing ?q= from injecting text into the chatbot input and requiring manual input instead.
