Anthropic Education Report: The AI Fluency Index · Claude Academy

Anthropic has released a report detailing the “AI Fluency Index,” quantifying how people effectively collaborate with AI. Using the 4D AI Fluency Framework—defining 24 behaviors, 11 of which are observable in conversations—they analyzed 9,830 anonymized Claude.ai conversations from January 2026. The study found that 85.7% of conversations involved “iteration and refinement,” repeatedly building on prior exchanges, and these conversations exhibited 2.67 additional fluency behaviors on average, including more questioning of Claude’s reasoning (5.6x more likely) and identification of missing context (4x more likely).

This suggests outputs perceived as ‘finished’ receive less scrutiny. The report highlights the importance of iterative conversation and critical assessment of AI outputs, and provides a baseline for tracking AI fluency as models evolve. The study acknowledges limitations relating to the sample population and the partial coverage of the framework.

Reducing cost and improving performance with Claude Platform | Claude by Anthropic

Anthropic’s blog post details techniques for reducing costs and improving performance when using the Claude Platform. The core of the announcement revolves around optimizing three key areas: prompt caching, instruction refinement, and effort calibration. For prompt caching, the article stresses the importance of byte-exact matches for cache hits, avoiding changes to settings like ‘effort’ mid-conversation (though this is possible with Claude Opus 5 and Fable 5.1), and keeping dynamic values out of the prompt prefix to maintain cache validity.

Regarding instructions, the post identifies common “anti-patterns” in prompts – like excessive verification requests or overly thoroughness instructions – that can lead to increased token usage and reduced performance with newer Claude models (Opus 5 and Fable 5.1). Anthropic provides a claude-api skill (/claude-api prompt-audit) to automatically detect and remove these problematic instructions. Finally, the post discusses the ‘effort’ parameter, noting that performance gains diminish at very high effort levels and that stronger models can achieve comparable results at lower effort settings. /claude-api hillclimb and /claude-api cost-optimize are new tools for automating these optimizations.

Previewing the Model Hardware Standard

Anthropic has announced a research preview of the Model Hardware Standard (MHS), a specification designed to allow AI agents to safely and efficiently operate physical devices. Developed in collaboration with HHMI Janelia Research Campus, MHS aims to reduce integration time for lab and manufacturing equipment—currently weeks or months—to hours or minutes by standardizing communication between devices.

The standard introduces a universal “driver” that translates commands like “read” and “write” for any programmable device, using a simple set of primitives and enabling discoverability across networks. The driver also incorporates natural language descriptions of device characteristics, automatically creating reference files for AI agent understanding. Anthropic reports early tests with Claude demonstrate the AI can learn to operate devices, and even write deterministic scripts for automated tasks, such as laser alignment.

Initial partners including Genentech, QuEra Computing, and Carnegie Mellon University have tested MHS, reporting speed increases in experiments and simplified automation. Anthropic is inviting stakeholders to join the research preview, with plans to eventually open-source the standard after further safety evaluations and developer input, and is already seeing support from companies like Amazon Web Services, Automata, and Raspberry Pi.

How Warp builds self-improving agents on Claude | Claude by Anthropic

Warp has developed a self-improvement loop for agents built on the Claude Platform, utilizing a “skills”-based framework. Skills are file-based encodings of knowledge, keeping instructions separate from the prompt itself. This system employs two primary skills: a “base skill” containing domain knowledge for a specific task (like code review), and an “improver skill” that periodically analyzes human feedback on the base skill’s output.

The process involves capturing human feedback – ideally detailed explanations, not just simple approvals – and using the improver skill to propose small, focused edits to the base skill. These edits are submitted as pull requests, allowing for review and approval before being merged, thus continuously refining the agent’s performance. Warp has deployed this pattern across its open-source repo, for tasks like issue triage and spec writing.

Key recommendations from Warp include writing skills as guiding principles rather than rigid rules, explaining the rationale behind them, minimizing friction for providing feedback, and prioritizing quality feedback over quantity. They emphasize the reusability of the “improver skill” across different agent applications and the importance of maintaining human oversight in the loop.

The AI-Native SDLC playbook | Claude by Anthropic

Anthropic’s blog post details how to transform the Software Development Lifecycle (SDLC) to fully leverage AI, specifically their Claude Code model. The core claim is that, with AI handling code generation, the bottleneck in development has shifted away from writing code itself and toward planning, review, testing, and deployment. To address this, they propose an “AI-native SDLC” – a looped process embedding AI at each stage – replacing the traditional linear flow.

This involves creating committed artifacts at each stage (like intent.md for initial ideas, spec.md for design, and plan.md for implementation plans) stored in version control, which then trigger the next phase. They introduce "plays" – modular steps for integrating Claude into each SDLC stage – focusing on automated handoffs and continuous evaluation. Key to this is using Claude to synthesize requirements from stakeholders into machine-readable formats, automating design tasks, generating code with integrated tests, and using AI-driven review layers alongside human oversight, particularly for critical or regulated code.

The post emphasizes institutional knowledge as code, through CLAUDE.md files that maintain project-specific context, and "skills" – reusable, versioned instructions applied by Claude to enforce standards and policies. They also discuss leveraging hooks for deterministic guardrails and the use of parallel sessions and sub-agents to increase engineer throughput.
