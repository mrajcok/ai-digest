Stop guessing auto scaling targets for TTS on Amazon SageMaker AI

  • This post details a method for automatically determining auto scaling targets for a text-to-speech (TTS) endpoint using Amazon SageMaker AI, specifically with the Kokoro-82M (82-million-parameter) model.
  • The approach replaces guesswork with two measured values: Q_max (maximum concurrency per instance before breaching SLO) and T_total (total scale-out time), deriving scale-in/out thresholds and cooldowns through arithmetic.
  • The methodology utilizes the ConcurrentRequestsPerModel metric native to Amazon SageMaker AI, avoiding the need for custom metric emission, and addresses the shortcomings of default auto scaling metrics for TTS due to its non-autoregressive nature.
  • Deployment is managed via AWS CDK stacks, ensuring a measured plan exists before auto scaling resources are created, and a command-line toolchain automates the measurement process – drift check, Q_max measurement, T_total measurement, and plan generation – with a focus on accurately determining scale-out parameters.

Securing AI agent identity with X.509 PKI on AWS

Securing AI agent identity is achieved through a reference architecture utilizing X.509 PKI with AWS services and Keyfactor EJBCA.

  • The architecture employs three authentication layers – User Auth, Agent-to-Agent, and MCP Auth – each leveraging signed request envelopes (proof-of-possession via RSA-PSS-SHA256), user-signed delegation assertions, RFC 8693 audience-scoped tokens, and real-time OCSP revocation checking.
  • The solution utilizes Amazon Bedrock (via Strands Agents SDK), Amazon RDS for MySQL, Amazon SES, and AWS Secrets Manager in conjunction with Keyfactor EJBCA for certificate lifecycle management and PKI operations.
  • Private keys are generated locally and never transmitted, with certificates issued via CSRs sent to EJBCA for signing, then stored in AWS Secrets Manager as PKCS12 bundles.
  • Replay prevention is implemented via unique nonces within signed envelopes and a freshness window, combined with timestamp validation, preventing unauthorized access through replay attacks or stale requests.

Beyond the KV cache: Training and serving i14’s Laplace 3B linear attention model on AWS Trainium2 with native PyTorch

Laplace 3B, a 3.028B parameter linear attention model from i14, was successfully trained and served on AWS Trainium2 using native PyTorch via TorchNeuron Native.

  • Laplace 3B utilizes Gated Linear Attention (GLA) to maintain a fixed recurrent state of 29.5MB per sequence, independent of context length, addressing KV cache growth issues in traditional transformers.
  • Training achieved 120,000 tokens/second on a trn2.48xlarge instance, while inference reached 11,544 output tokens/second across 1,280 concurrent sequences.
  • Key implementation changes included rewriting the GLA kernel with standard PyTorch, optimizing Muon communication with all_to_all collectives (reducing traffic by 24x and increasing throughput by 1.63x), and statically unrolling the GLA recurrence for the Trainium2 compiler.
  • The model's architecture features 24 decoder layers, a hidden dimension of 3,072, and a geometric decay schedule for attention heads, along with modifications to leverage the software-managed on-chip memory (SBUF) and fast interconnect of Trainium2.

Improve TTFT for multi-turn agentic workloads with bi-directional KV transfer in vLLM

  • AWS has implemented bi-directional KV cache transfer in vLLM (v0.21.0 or later) to improve Time To First Token (TTFT) for multi-turn agentic workloads.
  • The system allows decode nodes to return previously computed KV cache to prefill nodes, avoiding redundant recomputation of context and reducing accelerator capacity usage.

  • Benchmarks on Amazon EC2 P5en instances with EFA showed TTFT reductions of up to 1.6x for Qwen3-32B and 3.3x for zai-org/GLM-5-FP8 compared to not using the bidirectional transfer, especially with longer prompts.

Push-based KV transfer to improve TTFT and TPOT for disaggregated inference in vLLM

  • This blog post details a new “push-based” NVIDIA Inference Xfer Library (NIXL) connector in vLLM designed to improve Time-To-First-Token (TTFT) and Time-Per-Output-Token (TPOT) for disaggregated LLM inference.
  • The push-based connector overlaps KV cache transfer coordination with prefill computation by having the decode instance register target blocks before prefill completes, initiating transfer as soon as blocks are ready – eliminating a round trip present in the default “pull” mode.
  • The implementation utilizes a dedicated background thread on the prefill instance to handle KV transfer preparation and submission, further isolating this work from the critical path, and supports different block layouts on each side.
  • Benchmarks using the Qwen3-32B model on Amazon EC2 P5en instances with EFA show up to a 3x improvement in TTFT and a 30% improvement in TPOT with the push-based connector, particularly at higher request rates and longer input lengths.
