Trust in Depth: Giving agents more autonomy without losing control

AWS introduces “Trust in Depth,” a framework for increasing agent autonomy while maintaining control, focusing on four key areas: Scope, Know, Bound, and Observe.

  • Scope defines an agent’s permitted actions and data access through policies, utilizing tools like Kiro for rigorous build practices and Amazon Bedrock AgentCore for governance controls and automated reasoning to identify policy gaps or contradictions.
  • Know ensures every agent has a verifiable identity tracked through the AWS Agent Registry and enforced by AgentCore, linking every action to a specific authorized agent.
  • Bound enforces policy limits on agent behavior using AgentCore Gateway and Amazon Bedrock Guardrails, preventing unintended outcomes even with potential agent manipulation, and supports temporal policies that adjust access based on task progress.
  • Observe uses Amazon CloudWatch Omni to capture detailed execution traces, evaluate agent performance, and facilitate continuous improvement based on real-world behavior, enabling investigation and refinement of agent actions.

Beyond hours saved: Building the business case for agentic automation

Agentic automation business cases require a new framework beyond traditional ROI calculations focused on hours saved, as most value lies around the automated task rather than in the task itself.

  • The Agentic Value Model measures four key dimensions: time savings (extending RPA capabilities), exception handling (cost of corrections and errors – potentially 1.5–4x original transaction cost, with errors accounting for 2–15% of operational cost), decision quality (consistent policy application with logged rationale), and change resilience/maintenance (avoiding brittle script maintenance).
  • Value realization—converting operational improvements into economic gains—is critical; simply freeing capacity doesn't guarantee savings without a clear mechanism for redirecting capacity or reducing spend.
  • Amazon Quick Automate (within Amazon Quick) is highlighted as a service providing execution data to measure these value pools alongside operational and financial KPIs.
  • Workflow prioritization should be based on task complexity (reasoning required) and decision risk (cost of errors), using a two-by-two matrix to guide whether to use RPA, full automation, human-in-the-loop agents, or improved controls.
