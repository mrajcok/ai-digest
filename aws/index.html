Configure rate limits for AI traffic on AgentCore gateway

  • Amazon Bedrock AgentCore gateway now supports rate limiting, providing fine-grained control over AI traffic consumption by users.
  • Rate limits can be defined based on requests per minute/second (RPS/RPM), tokens per minute (TPM – for inference targets only), and connections per second (CPS).
  • Dimension keys like targetName, toolName, qualifiedModelId, JWT claims ($.context.jwt.<claim>), and IAM information ($.context.iam.principal, $.context.iam.sourceIdentity) can group traffic into rate buckets.
  • Rate limiting is layered: customer-defined limits are evaluated first, then Service Quotas, with the effective rate being the minimum of the two. AWS CLI examples are provided for configuration.

Securing AI agents with temporal policies in Amazon Bedrock AgentCore

Temporal policies in Amazon Bedrock AgentCore enable stateful authorization rules for AI agents by evaluating requests within the context of their session history.

  • Temporal policies leverage Dogwood, a new open-source governance language compatible with existing Cedar policies, to define conditions and rules.
  • Policies operate at the AgentCore Gateway, outside the agent’s code, preventing bypass and governing Model Context Protocol (MCP) calls (tool calls, agent-to-agent, and model inference).
  • They utilize agent trajectories – bounded sequences of actions identified by principal and session ID – with a 24-hour look-back window, and invalidate sessions upon policy changes.
  • Use cases include enforcing workflow sequencing, preventing data fabrication, capping cumulative financial exposure, requiring human approval, and ensuring data freshness.

Automated Reasoning policy refinement in Amazon Bedrock

  • Amazon Bedrock now offers automatic policy refinement to automate the process of diagnosing and fixing issues in Automated Reasoning policies, reducing manual effort.
  • Two new refinement modes are available: Iterative Refinement addresses rule issues by proposing edits to formal logic, while Ambiguous Variable Refinement resolves language issues by suggesting clearer variable descriptions.
  • Iterative Refinement requires a source document and optional feedback, analyzing divergence from the document to propose rule or variable changes, and uses an asynchronous API workflow (start, poll, retrieve).
  • Ambiguous Variable Refinement identifies overlapping or incomplete variable definitions causing translation issues and proposes refined descriptions, utilizing the same API workflow as Iterative Refinement but without the need for a source document or tests.
