Custom reward functions for multi-turn reinforcement learning with Amazon Nova Forge

Custom reward functions are critical for effective multi-turn reinforcement learning with Amazon Nova Forge, particularly when using reinforcement fine-tuning (RFT) and Group Relative Policy Optimization (GRPO).

  • Amazon Nova Forge allows you to bring your own orchestration (BYOO) to run reward logic in your environment for multi-turn RL, handling rollouts, message passing, and state across turns.
  • RFT uses a reward function—code you write—to score model outputs and adjust weights to maximize cumulative reward across a sequence of interactions, unlike supervised fine-tuning which relies on annotated examples.
  • Effective reward design combines outcome rewards (goal completion), behavioral rewards (desired intermediate steps), and penalties to discourage failures—ensuring a balanced learning signal and preventing gaming of individual components.
  • When executing model-generated code within the reward function, security measures like isolated environments, resource limits, and input/output validation are essential to prevent exploitation and maintain system integrity.

Tiered KV cache for large LLMs on Amazon SageMaker HyperPod with Curvine

AWS introduces a tiered KV cache architecture for large language model (LLM) inference on SageMaker HyperPod, utilizing Curvine for a shared, distributed NVMe pool.

  • The architecture implements a three-tier cache: L0 (GPU HBM), L1 (local CPU/host memory), and L2 (Curvine, shared NVMe), coupled with intelligent request routing.
  • Curvine is a distributed cache filesystem pooling node-local NVMe drives into a shared namespace accessible via a FUSE client as a ReadWriteMany PVC.
  • HyperPod’s Intelligent Routing directs requests to replicas with the best prefix match to maximize cache hits, supporting prefix-aware, kv-aware, and round-robin strategies.
  • The solution aims to reduce costs by enabling the use of lower-cost instances (e.g., G6e) for workloads that previously required more expensive instances (e.g., P5), achieving up to a 2.7x TTFT improvement and 100% cross-Pod cache hit rate in testing.
