Improve TTFT for multi-turn agentic workloads with bi-directional KV transfer in vLLM

  • AWS has implemented bi-directional KV cache transfer in vLLM (v0.21.0 or later) to improve Time To First Token (TTFT) for multi-turn agentic workloads.
  • The system allows decode nodes to return previously computed KV cache to prefill nodes, avoiding redundant recomputation of context and reducing accelerator capacity usage.
  • Key components include enhancements to the NVIDIA Inference Xfer Library (NIXL) KV connector, a KV-cache-aware router (a lightweight, stateful control plane), configurable block retention TTL (default 480 seconds) and a KV recompute threshold (default 64 tokens).
  • Benchmarks on Amazon EC2 P5en instances with EFA showed TTFT reductions of up to 1.6x for Qwen3-32B and 3.3x for zai-org/GLM-5-FP8 compared to not using the bidirectional transfer, especially with longer prompts.

Push-based KV transfer to improve TTFT and TPOT for disaggregated inference in vLLM

  • This blog post details a new “push-based” NVIDIA Inference Xfer Library (NIXL) connector in vLLM designed to improve Time-To-First-Token (TTFT) and Time-Per-Output-Token (TPOT) for disaggregated LLM inference.
  • The push-based connector overlaps KV cache transfer coordination with prefill computation by having the decode instance register target blocks before prefill completes, initiating transfer as soon as blocks are ready – eliminating a round trip present in the default “pull” mode.
  • The implementation utilizes a dedicated background thread on the prefill instance to handle KV transfer preparation and submission, further isolating this work from the critical path, and supports different block layouts on each side.
  • Benchmarks using the Qwen3-32B model on Amazon EC2 P5en instances with EFA show up to a 3x improvement in TTFT and a 30% improvement in TPOT with the push-based connector, particularly at higher request rates and longer input lengths.

How Deepgram optimized voice AI at scale with AWS Trainium

Deepgram optimized its Nova-3 speech-to-text model for AWS Trainium2, achieving significant cost and performance gains.

  • The Nova-3 model was ported from standard PyTorch code to AWS Trainium2 using TorchNeuron and compiled with torch.compile for full hardware utilization.
  • Performance was further enhanced by replacing layers with fused kernels from the Neuron Kernel Interface Library (NKILib) and custom-written kernels, addressing bottlenecks in FFN layers, depthwise convolutions, and 2D convolutions.
  • A data-parallel Rust runtime was built to leverage eight physical NeuronCores per Trainium2 device, improving throughput and reducing overhead compared to Python-based runtimes—achieving up to 7.5% gain.
  • The optimized configuration processed 11–70 percent more audio per dollar compared to previously used compute options on Deepgram’s offline batch workloads.

Trust in Depth: Giving agents more autonomy without losing control

AWS introduces “Trust in Depth,” a framework for increasing agent autonomy while maintaining control, focusing on four key areas: Scope, Know, Bound, and Observe.

  • Scope defines an agent’s permitted actions and data access through policies, utilizing tools like Kiro for rigorous build practices and Amazon Bedrock AgentCore for governance controls and automated reasoning to identify policy gaps or contradictions.
  • Know ensures every agent has a verifiable identity tracked through the AWS Agent Registry and enforced by AgentCore, linking every action to a specific authorized agent.
  • Bound enforces policy limits on agent behavior using AgentCore Gateway and Amazon Bedrock Guardrails, preventing unintended outcomes even with potential agent manipulation, and supports temporal policies that adjust access based on task progress.
  • Observe uses Amazon CloudWatch Omni to capture detailed execution traces, evaluate agent performance, and facilitate continuous improvement based on real-world behavior, enabling investigation and refinement of agent actions.
