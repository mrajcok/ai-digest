Amazon SageMaker Feature Store introduces UpdateRecord for feature-level writes

  • Amazon SageMaker Feature Store now offers UpdateRecord API for feature-level writes, eliminating the read-modify-write cycle previously required with PutRecord.
  • UpdateRecord supports atomic updates to specific features within a record, preserving existing values and preventing race conditions; requires either the Standard_V2 storage format (DynamoDB-backed) or works directly with the existing In-Memory (ElastiCache-backed) tier.
  • Migration to the new Standard_V2 storage format can be achieved via bulk migration using the Feature Processor SDK (Strategy A) or an in-place update using the UpdateFeatureGroup API (Strategy B - recommended).
  • New IAM condition keys, sagemaker:IsUpdateRecord and sagemaker:UpdatableFeatures, allow for fine-grained access control over which features can be updated by specific principals.

Designing lifecycle policies for AgentCore memory

Memory lifecycle management for Amazon Bedrock AgentCore helps maintain agent effectiveness by managing retained information.

  • The solution introduces three lifecycle policies: TTL-based expiration (defaulting to 90 days for episodic memories), relevance decay scoring (using recency, access frequency, and a configurable pruneDays parameter), and LLM-based consolidation (using Amazon Bedrock to summarize and merge memories).
  • AgentCore memory categorizes memories into Episodic, Semantic, and Procedural types, each with different retention requirements and strategies for storage and management.
  • Relevance scoring utilizes a weighted formula – `score = W_RECENCY
  • exp(-decay_rate
  • days_since_creation) + W_ACCESS
  • exp(-decay_rate
  • days_since_last_access) + W_FREQUENCY
  • min(access_count / MAX_ACCESS_BASELINE, 1.0)– and derives a decay rate from apruneDays` parameter to determine memory relevance.
  • The architecture uses Amazon EventBridge, AWS Step Functions, and Lambda functions to orchestrate a nightly lifecycle workflow, tracking access via AWS CloudTrail and persisting results in Amazon S3, with failure notifications sent via Amazon SNS.
